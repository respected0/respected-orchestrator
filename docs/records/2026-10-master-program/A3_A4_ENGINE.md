## A3 — implemented (`antigravity_orchestrator.py`, `runner.py`)
- `collect_worker_changes(lane, ownership)` splits untracked/ignored paths into real changes and `ChangeSet.generated`; `export_worker_patch(lane, output, ownership)` only adds real untracked files, so generated output never enters `worker.patch` and never reaches apply. The legacy antigravity flow passes ownership too.
- Classification (only for paths that are untracked or ignored; tracked files are always real changes, including a tracked `.pyc`): ALWAYS generated: `__pycache__`, `*.pyc/.pyo`, `*.egg-info`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.hypothesis`, `.tox`, `.nox`, `.ipynb_checkpoints`. Build-looking directories (`build`, `dist`, `target`, `node_modules`, `.venv`, `venv`, `.eggs`, `htmlcov`, `.next`, `.turbo`, `src-tauri/gen`) are generated when git ignores the path OR the repository tracks nothing inside them; a tracked, un-ignored `build/` stays source (fail closed). An ownership entry that itself points into such a location (`dist/notes.md`) authorises exactly that path.
- Safety unchanged: symlinks/junctions leaving the worktree stay `unsafe_paths` (never hidden as generated); real out-of-scope files still produce `scope_violation` and the report lists only real files; `integration_conflict` (patch vs master) and stale-project checks are untouched; `include_untracked_owned` and untracked owned inputs keep working; nothing is deleted. Results record `generated_artifacts` (first 100) and `generated_artifact_count` so ignoring is visible.

## A4 — implemented (`budget.py`, `maf_workflow.py`, `project.py`, `campaign.py`, `runner.py`)
- `workflow.max_weighted_tokens` (1000..50M, optional) = hard lane budget; `workflow.unknown_step_tokens` (default 50,000) = assumed charge per unknown step. Lifetime across retries, corrections and re-invocations (computed from the signed attempt history and `review-attempts.json`, not from a counter that a retry could reset). Checked before every paid step: a new or correction worker, every review attempt including deep review and retries. Usage arrives only when a codex turn completes, so enforcement is at step boundaries (worst overshoot = one step); a budget stop returns `token_budget_exceeded`, approves nothing, keeps the verified patch (review-only retry still possible) and never rewrites history.
- UNKNOWN is explicit: a step that was launched but reported no usage counts as unknown (`usage_status` KNOWN/PARTIAL/UNKNOWN/NONE, `unknown_usage_steps`); reported `token_usage` stays the known sum; the assumed charge appears only in `token_budget.basis`. A step refused before launch (e.g. `stale_project`) costs nothing and is not counted.
- Project level: phase `lane_token_budget` (or the lane's own `max_weighted_tokens`) is cumulative over the phase's attempts: a fresh worker run gets `limit - spent_by_that_lane` (a resumed review-only lane keeps its own run ledger, no double counting); below 1000 left the supervisor blocks with "lane X exhausted its token budget" before creating a campaign. Project budget `unknown_step_tokens` charges unknown steps in the project budget check and `unknown_usage_steps` is reported next to `weighted_tokens` (it no longer assumes 0).
- Corrections now sum every worker attempt of an invocation (before, only the last round's worker usage was counted).
- Cached-input: `cached_cost_share` per invocation in `maf-usage.json` and the result; a safe optimisation in the worker brief (`Token discipline` paragraph: read only needed ranges, do not re-read, short command output). Its effect is NOT yet measured; the budget is the hard safety net. Next measurement belongs to the live smoke (A9).
- Classification kept: timeout / provider disconnect / scope_violation / integration_conflict / test_failed / worker_failed unchanged; `token_budget_exceeded` is a distinct reason carried into lane summaries (`token_usage_status`, `unknown_usage_steps`, `token_budget`).
